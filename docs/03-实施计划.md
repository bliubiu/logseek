## 1. 计划目的

将 PRD 范围与架构方案拆解为可执行、可验收、可回滚的迭代计划：明确阶段目标、任务分解、测试策略、里程碑、风险与完成定义（DoD），指导 TDD 落地与逐次 Git 提交。

## 2. 实施原则

1. **TDD**：先写行为测试，再写实现；核心模块 1–4 测试必达（PRD 5.2）。
2. **深模块小步提交**：每个可独立验收的变更对应一次 Git commit，信息中文可追溯。
3. **依赖单向**：按架构分层落码，禁止 CLI 直捅文件细节、领域层引入 Cobra/SQLite。
4. **只读铁律**：任何阶段的集成测试都须覆盖「源文件校验和不变」。
5. **文档同步**：行为或接口与 01/02 不一致时，先改文档再改码；每次迭代更新 CHANGELOG。
6. **范围克制**：SQLite、偏移加速、并行扫描等非首期项不得提前进入关键路径。
7. **资源红线优先**：PRD §4.3.1 / 架构 §6.1 的 RSS、单行、并发、句柄、网络、I/O 红线为发布门禁；实现不得默认关闭软内存上限。

| ID | 任务 | 产出 | 验收 |

### 4.2 阶段 1：文件预检探测（模块 1）

| ID | 任务 | 说明 | 测试焦点 |
| :--- | :--- | :--- | :--- |
| 1.1 | 只读打开与错误分类 | 权限/不存在/空文件中文错误 | 退出类别、中文信息 |
| 1.2 | 头尾 `ReadAt` 采样与行恢复 | 跨采样边界完整行 | 单行/无换行文件 |
| 1.3 | 编码探测 | UTF-8 优先，GBK 等候选 | UTF-8、GBK 夹具 |
| 1.4 | 时间格式候选打分 | 接 `timefmt` 最小候选集 | 已知格式命中、未知降级 |
| 1.5 | 探测报告结构与文本输出 | 字段完整、含示例行 | 外部可观察报告内容 |

## 5. 测试与质量计划

### 5.1 策略

| 层级 | 对象 | 方式 |
| :--- | :--- | :--- |
| 单元 | 模块 1–4 领域行为 | TDD；合成夹具；外部行为断言 |
| 集成 | 管线组合、摘要 | 临时文件端到端 |
| 端到端 | CLI → 退出码/输出 | 少量黑盒，覆盖主路径 |
| 性能 | 对抗样例、大文件基准 | 回归测试 + 阶段 5 基准记录 |
| 资源 | RSS/单行/句柄/并发/网络默认档 | 阶段 5.5 红线门禁；与 01 §4.3.1、02 §6.1 对照 |
| 安全 | 只读、密钥失败、脱敏 | 行为测试；禁止明文密码日志 |

### 5.2 必绿门禁（每次交付前）

1. `go test ./...` 全绿（含阶段引入的对抗样例）。
2. 核心四模块覆盖的关键路径有测试（PRD 5.2 表）。
3. 源文件只读校验通过。
4. 全部用户可见错误/摘要为中文。
5. CHANGELOG 与相关 docs 已更新。
6. 对应 Git commit 已创建（信息中文）。
7. **资源红线抽查**（发布前必过）：GOMEMLIMIT 默认开启；单行 1MiB；无无界并发；句柄 ≤8；默认无网络；全量扫描满足 RSS ≤256MiB。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
| :--- | :--- | :--- |
| 尚未 git 仓库 | 无法按规范提交 | 阶段 0.6 优先完成；远程推送需确认 |
| 时间边界语义不清 | 边界行争议 | 阶段 3.2 测试钉死并回写 02 |
| 回归正则误入核心 | 性能漏洞 | 代码评审门禁 + 阶段 2.6 |
| 范围蔓延（DB/并行） | 延期 | 阶段 6 隔离；首期 DoD 不含 |
| 超长行/恶意文件 | 内存尖峰 | 单行 1MiB 硬上限（R-LINE）；计入错误/坏行 |
| 生产机资源挤占 | 影响线上业务 | §5.2 门禁 7 + 阶段 5.5；默认顺序 + nice/ionice 文档 |
| 密钥/脱敏接线遗漏 | 安全违规 | 阶段 4.3–4.6 行为测试门禁 |
| 中途失败残缺输出 | 用户误判 | 阶段 6 原子写；首期文档提示 |

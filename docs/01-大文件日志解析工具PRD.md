## 1. 问题陈述

运维与开发人员在排查线上问题时，经常面对数 GB 甚至数十 GB 的单体日志文件。现有通用工具存在明显短板：

- 文本编辑器或 `less` 直接打开大文件会卡顿、内存溢出，无法交互。
- 通用搜索引擎（如 grep 全量扫描）缺少时间维度，难以按故障时间窗口快速收敛范围，重复扫描代价高。
- 命令行工具普遍不感知日志时间戳格式与文件编码，跨系统复制来的日志难以统一按时间切片。
- 部分脚本会就地改写或截断源日志，存在破坏现场证据的风险。
- 输出结果若含手机号、身份证号等敏感信息，直接外发存在合规风险。

用户需要一款**只读源日志、可按时间与内容双维度过滤、可在大文件上快速预检并稳定产出结果文件**，并且在**线上生产机上以极低系统资源运行、不挤占业务 CPU/内存/磁盘 I/O** 的命令行解析工具。

## 2. 解决方案

从用户视角，logSeek 提供一条完整的「预检 → 切片 → 检索 → 导出」工作流：

1. **预检**：对目标日志做头尾随机读（`ReadAt`），秒级探测文件编码、时间戳格式、首末时间范围与大致行数，不整读文件。
2. **时间切片**：按用户给出的起止时间（或相对时间，如「最近 2 小时」）只保留区间内日志行，支持时间格式覆盖失败时的显式指定。
3. **内容检索**：在切片结果上叠加关键词或正则匹配，支持大小写敏感、整词、多关键词与或关系；匹配优先字节扫描与 FSM/DFA，规避正则性能漏洞。
4. **流式导出**：分块流式读取源文件，命中行按序写入输出文件；源日志全程只读，永不修改。
5. **配置与安全**：配置文件敏感字段按已有安全设计自动加解密；控制台与输出内容按规则脱敏。
6. **CLI 体验**：通过 Cobra 子命令暴露能力（如 `inspect` / `slice` / `grep` / `export`），参数可组合，错误信息全中文，退出码可被脚本消费。

1. 作为运维工程师，我希望对一个 20GB 的日志文件执行头尾预检，以便在数秒内知道其时间格式与覆盖时间范围，而不必将文件读入内存。
2. 作为运维工程师，我希望预检结果告诉我文件编码（UTF-8 / GBK 等），以便避免中文日志乱码后再做后续解析。

5. 作为运维工程师，我希望按相对时间切片（如最近 30 分钟、最近 7 天），以便快速回看近期窗口而无需手算时间戳。

## 4. 实现决策

### 4.1 总体架构

- 采用四层 DDD 架构与 TDD 开发方式；Go 1.25+，CLI 使用 Cobra。
- 依赖单向、边界清晰：CLI 层 → 应用服务层 → 领域层 → 基础设施层；领域层不依赖框架细节。
- 依赖单向选择 SQLite（`modernc.org/sqlite`，WAL 模式）仅在确有索引/缓存需求时引入，数据默认落 `data/`；首期解析链路不强制持久化。

### 4.2 将构建/修改的模块（深模块清单）

| 模块 | 职责 | 对外接口形态（概念） | 为何是深模块 |
| :--- | :--- | :--- | :--- |
| 文件预检探测 | 头尾随机 `ReadAt` 采样，识别编码、时间格式、首末时间、体量估计 | 输入：文件路径（可选格式提示）→ 输出：探测报告 | 内部封装采样策略、格式候选匹配、编码探测；接口稳定为「一次探测、一份报告」 |
| 时间切片引擎 | 解析每行时间戳并判定是否落在时间窗口 | 输入：行流 + 时间窗口 + 格式策略 → 输出：命中行迭代器 | 封装格式优先级、坏行策略、相对时间计算；接口不暴露解析细节 |
| 内容检索 | 关键词/正则匹配及布尔组合 | 输入：行流 + 检索条件 → 输出：命中行迭代器 | 封装字节扫描、FSM/DFA 匹配与 RE2 兜底、大小写与整词语义；调用方只感知条件 DSL |
| 流式读取输出 | 分块读源文件、组合上述过滤器、顺序写结果 | 输入：源路径 + 过滤器组 + 输出路径 → 输出：执行摘要 | 封装分块、背压、只读保障、摘要统计；唯一允许写文件的出口 |
| CLI 命令层 | Cobra 子命令、参数解析、退出码、中文帮助 | 用户命令与全局/子命令 flag | 薄层，编排应用服务，不承载解析逻辑 |
| 配置与安全 | 配置加载、`ENC()` 自动解密、输出脱敏接线 | 配置对象 + 脱敏中间件/包装 Writer | 对接 `00-安全设计`；密钥失败即终止，不降级 |

### 4.3 关键技术决策

- **只读约束**：源日志一律以只读方式打开；全工具唯一写路径是「输出结果文件 + 项目自身日志/数据目录」。
- **随机预检**：利用 `io.ReaderAt`（`os.File.ReadAt`）读取头部与尾部窗口，避免全量 I/O；探测失败时给出中文可操作提示。
- **时间模型**：内部统一解析为可比较的时间点；用户输入支持绝对时间与相对时间两种形态；格式未知时走候选库自动探测，失败则要求显式 `--time-format` 或降级为纯检索。
- **坏行策略**：无法解析时间的行按可配置策略处理（默认丢弃并计数，计数进入执行摘要），保证结果可解释。
- **匹配性能（强制）**：内容检索与一切模式识别**优先字节扫描、FSM/DFA 机制**（如 AC 自动机、DFA 子集匹配、滑动窗口字节比较），规避正则表达式性能漏洞与 ReDoS/正则 DoS 风险；禁止引入回溯型正则作为核心路径。仅在 FSM/DFA 无法表达的复杂模式时，才允许降级使用 **RE2 语义**（无回溯）正则，且必须包在同一匹配抽象之后、可被替换；该原则与 `00-安全设计` 脱敏引擎选型完全一致。
- **流式管线**：按固定块大小读取 → 行切分 →（可选）时间过滤 →（可选）内容过滤 → 写出；全链路流式，内存与文件大小解耦。
- **组合语义**：同时给出时间与内容条件时为「与」关系；多关键词之间由显式开关选择「与 / 或」。
- **输出与摘要**：结果写入 `--output` 指定文件；标准输出打印中文摘要（扫描行、命中行、坏行、耗时）；错误退出码区分参数错误、文件不存在、探测失败、运行中断等类别。
- **安全接线**：配置敏感字段遵循 `ENC()` 格式与算法标签路由；日志与对外输出走脱敏规则；日志系统按 AGENTS.md 规范（级别、格式、按日轮转、保留 32 天）。
- **语言与编码**：代码注释、日志、CLI 文案、错误信息、文档全部中文；文件 UTF-8 无 BOM。
- **生产共存（强制）**：工具定位为**极低资源、可与线上业务同机共存**。默认执行「单进程 + 顺序流式 + 有界缓冲」；资源红线见下表，违反红线不得发布。

#### 4.3.1 资源使用红线（默认档 / 生产推荐档）

| 维度 | 红线 | 说明与业界依据 |
| :--- | :--- | :--- |
| 内存（RSS） | 全量扫描 10GB 级日志时 **RSS 峰值 ≤ 256 MiB**；Go 软内存上限默认 **GOMEMLIMIT ≈ 192 MiB**（可配置，不得默认关闭上限） | `runtime/debug.SetMemoryLimit` / `GOMEMLIMIT` 软限制（Go 官方 GC 指南） |
| 单行长度 | **单行 ≤ 1 MiB**；超出按超长行策略截断或跳过并计数，**禁止无界拼接** | 防恶意/异常行内存尖峰 |
| 读写缓冲块 | 默认块大小 **1 MiB**（允许 256 KiB–4 MiB 档位）；禁止整文件一次读入或整文件 mmap 常驻 | 流式解耦文件体积 |
| CPU 占用 | 默认**顺序管线、单飞处理**；可选并行时并行度 **≤ min(2, max(1, NumCPU/2))**，禁止无界 goroutine 扇出占满全核 | 顺序管线（ADR）；生产推荐 `nice -n 10`（最高可到 19） |
| 磁盘 I/O | **顺序缓冲读**；生产推荐 `ionice -c 3`（idle）或 `ionice -c 2 -n 7`；可选 `--read-rate` 生产默认建议 **≤ 64 MiB/s**（可显式关闭） | `ionice` idle 档：对正常系统活动影响应为零（man7 ionice）；`renice 19`：仅在系统无其他需要时运行 |
| 文件句柄 | 进程同时打开文件数 **≤ 8**（源 + 结果 + 日志等） | 最小化资源占用 |
| 网络 | **默认零网络访问**（与范围外 HTTP 一致） | 本地按需解析器 |
| 结果写出 | 带缓冲写 + 批量刷新；**禁止逐行 fsync** | 降低写放大与 I/O 抖动 |

生产机启动建议（文档向，不强制改码实现包装器）：`nice -n 10 ionice -c 3 logseek ...`；容器场景可由编排层限制 `cpu.max` / `memory.max`，工具自身仍须满足上表默认红线。

### 4.5 Schema / API

- 首期无对外 HTTP API；能力全部经 CLI 暴露。
- 预检报告、执行摘要为进程内结构化对象，序列化为中文可读文本/JSON 输出供人与脚本消费（具体格式在实现阶段定稿）。
- 若引入 SQLite：仅存放派生索引/元数据，不复制源日志正文；WAL 模式；删除数据目录不影响源日志完整性。

## 5. 测试决策

### 5.1 何为好测试

- 只测外部可观察行为（给定输入文件与参数 → 输出内容、摘要、退出码），不断言内部私有实现、私有函数调用次数或具体算法分支。
- 测试数据使用小型合成日志夹具（含中文、多时间格式、坏行、超长行），不依赖真实生产日志。
- 失败信息与断言用中文可读，便于团队定位。

### 5.2 测试范围（用户已确认：模块 1–4）

| 模块 | 测试重点 |
| :--- | :--- |
| 文件预检探测 | 头尾采样正确识别已知格式；UTF-8/GBK 编码判定；空文件/单行/无时间戳文件的降级与中文错误提示 |
| 时间切片引擎 | 绝对/相对时间窗口边界（含起止闭开约定）；多格式命中；坏行计数与默认丢弃策略；乱序时间行为符合文档约定 |
| 内容检索 | 关键词大小写与整词；正则命中；多关键词与/或；无匹配时摘要正确；对抗性回溯型样例在字节扫描/FSM 路径下不出现超线性耗时（性能漏洞回归） |
| 流式读取输出 | 源文件校验和在执行前后不变（证明只读）；分块边界处行不被截断；输出顺序与源顺序一致；时间+内容组合为与关系；摘要数字正确 |

### 5.3 前例与方式

- 遵循项目 TDD 技能约定（先写测试再实现，接口设计保持深模块）。
- CLI 层以少量端到端黑盒测试覆盖「命令 → 退出码 → 输出文件」主路径；配置与安全层的密钥失败终止、脱敏规则以对接 `00-安全设计` 的行为测试为主（不在本次必测的 1–4 范围内强制展开，但随实现补充）。
- 每次改动必须补全/更新对应测试，交付前全量测试通过。

## 6. 范围外（Out of Scope）

- 图形界面、Web 服务、远程查询 API。
- 对源日志的任何写入、截断、轮转、压缩或清理。
- 分布式多机并行解析、集群调度。
- 日志采集/Agent 常驻推送（本工具是本地/挂载路径上的按需解析器）。
- 非文本类日志（二进制容器、压缩包内直接解析；压缩包解压后按普通文件处理可后续再议）。
- 智能异常检测、根因分析、日志语义理解（LLM/规则引擎类告警）。
- 首期强制 SQLite 索引持久化（能力保留为可选，非本 PRD 必达）。
- 多语言（非中文）文档与 CLI 文案。

## 7. 补充说明

- **性能与资源验收口径**：在开发机上对 10GB 级 UTF-8 日志，预检应在秒级完成；时间切片+检索全量导出应稳定跑完。**资源红线为发布门禁**：RSS 峰值 ≤ 256 MiB、软内存上限默认生效、单行上限 1 MiB、默认顺序执行且无无界并发、句柄 ≤ 8、默认无网络。内容检索主路径须为字节扫描/FSM/DFA，以对抗性正则样例做性能回归，确保不出现回溯型正则的超线性耗时。基准中可附带记录吞吐与 nice/ionice 档位，供生产共存评估。
- **合规**：输出与日志脱敏规则以 `docs/00-安全设计.md` 为唯一规范；新增脱敏规则须同步该文档。
- **交付纪律**：每次改动完成后创建对应 Git commit；同步更新 CHANGELOG（CalVer）与本文档；测试全绿后再交付。
- **版本策略**：CalVer `YYYY.MM.DD.MICRO`，兼容标注遵循项目 CHANGELOG 规范。
- **待定项**：预检是否输出「时间偏移粗定位」以加速超大文件切片——作为实现阶段可选优化，不阻塞首期验收。
